# 코드 검증과 배포 용량 최적화

검증일: 2026-10-04 (한국 시간). 기준 커밋: `3397daf`.

## 변경

- 홈 장면과 여우 이미지를 같은 해상도·투명 배경으로 WebP 재압축했다. `next/image`의 정적 import와 `sizes`로 화면·픽셀 밀도에 맞는 변형을 제공한다. 해시가 있는 정적 자산이므로 이미지가 바뀌면 URL도 바뀐다. 홈 장면은 eager/high priority, 안내 캐릭터는 lazy로 불러온다.
- 이미지 원본은 `public/adventure`에서 `src/assets/adventure`로 옮겼다. 정적 import로 만들어진 해시 파일과 원본 public 파일이 함께 배포되는 중복을 피한다.
- 홈에서 쓰지 않는 지도 작업 화면·카카오 지도 선택기·분석·제안서·기능 설정은 해당 화면을 열 때 동적 import한다. 로딩 중에는 안내를 표시한다.
- 클라이언트에서 쓰는 Zod를 직접 namespace import하여 Turbopack이 사용하지 않는 모듈을 제외할 수 있게 했다. 스키마와 검증 기준은 유지한다.
- 과거 주제 계약은 `src/server/theme-history.ts`로 옮겼다. 과거 버전 조회 API는 계속 제공하며 현재 이모지 모음에 과거 계약을 함께 넣지 않는다.
- 검수 사진은 lazy loading, 사진 디코딩은 async를 사용한다. 권한이 필요한 관찰 사진은 기존 인증 API와 `private, no-store` 응답을 유지한다. 공유 이미지 최적화 API는 빌드된 정적 이미지 경로만 허용하며 관찰 사진 경로 요청은 400으로 거부한다.
- `.vercelignore`에 `outputs/`, `docs/qa/`, `tests/`, `*.tsbuildinfo`를 추가했다. 주제 계약 JSON은 빌드에 필요하므로 포함한다. [Vercel 제외 파일 문서](https://vercel.com/docs/deployments/vercel-ignore)에 따른 업로드 제외 설정이며, Git 배포에 원래 포함되지 않은 로컬 결과물까지 배포 절감량으로 계산하지 않았다.

JS는 같은 Next.js 버전의 최적화 빌드에서 HTML의 `<script src>`를 중복 없이 집계하고 gzip으로 계산했다. 이후 열리는 도구 청크·Kakao SDK·API·CSS는 제외하며 실제 CDN의 Brotli 전송량이나 로딩 속도 측정은 아니다. 개발용 JS 크기를 비교하지 않았다.

이미지 응답은 실제 로컬 `/_next/image`에 WebP Accept 헤더로 요청한 크기다. 390px 브라우저에서 홈 이미지가 384px 변형을 선택하는 것을 DOM과 화면으로 확인했다. 실제 기기는 DPR에 따라 750px 등 다른 크기를 선택한다. 다운로드 용량 감소가 같은 비율의 속도 개선을 의미하지는 않는다.

재측정: `npm run build` 후 `node scripts/measure-assets.mjs`. `ASSET_REPORT`로 JSON 저장 위치를 지정할 수 있다. 비교 원본과 결과 JSON은 로컬 `outputs/optimization/`에 보존했다.

## 검증 결과

- 기존 테스트 67개 통과, TypeScript·프로덕션 빌드 통과.
- `npm audit --omit=dev`: 보고된 취약점 0개. 모든 취약점이 없다는 보증으로 해석하지 않는다.
- 7개 마이그레이션의 30개 테이블·권한·교차 지도 FK 검사 통과. 이번 변경에는 DB 마이그레이션이 없다.
- 실제 로컬 API: 세션·공개 지도 목록·유니버설 디자인 주제 v1/v2 모두 200.
- 모바일 390px: 홈 이미지 표시, 카카오 지도와 표시 도구, 통계·제안서·설정 화면의 분리 로딩 확인. 확인 과정에서 사용자 데이터를 변경하지 않았다.
- 공유 이미지 최적화 API의 관찰 사진 경로 거부 확인. 관찰 사진의 기존 업로드 압축(최대 1600px, 서버 WebP)과 권한 검사는 유지한다.

운영 빌드를 로컬에서 실행할 때 기존 HTTP `APP_ORIGIN`은 HTTPS 운영 보호 규칙에 의해 거부된다. 환경 변수를 바꾸지 않고 개발 설정으로 로컬 UI를 검사하고, 운영 빌드는 실제 Vercel 배포에서 검사한다.
