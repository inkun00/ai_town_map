# 모두의 지도 — 모바일 참여형 커뮤니티맵 PRD

문서 버전: 1.3 · 작성일: 2026-09-27 · 상태: 주제별 기능·공통 이모지·단계별 개발 및 모델 사전 안내 반영, 세부 기본값은 권장안

## 1. 제품 정의

**누구나 주제별 지도를 만들고, 참여자들이 현장에서 장소를 기록·평가하며, 함께 모은 데이터를 근거로 우리 동네의 개선 방안을 제안하는 모바일 웹앱.**

가칭은 ‘모두의 지도(Map of All)’다. 카카오맵을 바탕으로 생태·안전·유니버설 디자인·날씨생활 등 다양한 주제를 지원한다. 하나의 지도가 하나의 조사 프로젝트이며, 지도마다 주제·참여자·분류·공개 범위와 주제에 맞는 기능 구성을 가진다. 지도 생성의 첫 단계에서 주제를 선택하면 핀 표현, 입력 양식, 평가 여부, 필터, 분석, 제안 기능이 함께 구성된다.

핵심 경험은 **주제 선택·지도 만들기 → 초대·참여 → 현장 발견·기록 → 지도에서 비교 → 데이터 분석**이며, 주제에 따라 **개선 제안 → 재관찰**로 확장한다.

### 1.1 확정된 사용자 요구사항

- 카카오맵 API를 지도 기반으로 사용한다.
- BioMap의 지도 선택·입장·관찰 등록 중심 구조를 참고한다.
- 사용자가 주제를 정해 여러 지도를 개설하고, 다른 이용자가 해당 지도에 위치포인트를 등록한다.
- 지도 생성의 첫 단계에서 주제를 선택하며, 선택한 주제에 따라 제공되는 기능이 일부 달라진다.
- ‘모두에게 편리 / 조금 불편 / 개선 필요’ 3색 핀은 해당 평가를 사용하는 주제에만 적용한다. 모든 지도에 공통 적용하지 않는다.
- 장소별 평가항목과 아이콘, 개선 아이디어 입력은 주제에 맞게 제공한다.
- 포인트에 사진·링크·설명·아이콘·댓글을 지원한다.
- 모든 지도는 주제에 맞는 다양한 이모지를 위치포인트 아이콘으로 제공한다. 개별 포인트에는 해당 관찰 유형을 나타내는 이모지 하나를 표시하며, 핀 색상 모드나 평가 기능 사용 여부와 관계없이 적용한다.
- 모바일 화면 구성, 화면 비율, 터치 조작을 우선한다.
- 첨부 자료의 안전·날씨 관찰, 데이터 분석, AI 검토, 개선 제안 활동을 제품 요구사항에 반영한다.

### 1.2 사용자 답변으로 확정한 제품 방향

학교·학급과 일반 커뮤니티를 모두 주요 사용자로 지원한다. 지도마다 공개·참여 범위를 선택하며, 개설자는 로그인하고 참여자는 초대 코드·닉네임으로 입장한다. 첫 출시에는 기본 통계·차트·수동 제안서를 포함하고 AI 분석은 후속 버전으로 둔다.

### 1.3 세부 기본값과 권장 가정

아래 기본값 중 별도 확정 표시가 없는 사항은 구현·파일럿 과정에서 조정할 수 있다.

| 결정 항목 | 초안의 권장안 | 변경 시 영향 |
|---|---|---|

| 공개 범위 | 지도별 선택 — 확정. 초기 선택값은 초대 전용 권장 | 검색 노출·열람 권한 |
| 로그인 | 개설자 로그인, 참여자는 초대 코드와 닉네임으로 게스트 참여 — 확정 | 본인 기록 복구·악용 방지 |

| 플랫폼 | 설치 없이 사용하는 반응형 모바일 웹 | PWA 설치·오프라인 동기화는 후속 검토 |

## 2. 참고 자료와 적용 원칙

### 2.1 BioMap에서 확인한 구조

2026-09-27에 [BioMap](https://biomap.kro.kr/)의 공개 UI를 확인했다.

| 지도 검색, 지도 카드, 포인트 수 | 주제별 지도 탐색 및 내 참여 지도 목록 |

| 개별 지도 입장 시 닉네임 입력 | 지도별 닉네임을 사용하는 가벼운 참여 흐름 |

| 발견생물·생태 퀴즈·분포도 제작·지도 합치기 버튼 | 범용 분류·통계 중심으로 재구성, 퀴즈·지도 병합은 후속 검토 |

개별 지도는 닉네임 입장 단계까지만 확인했다. 등록 완료, 관리자 권한, 분포도 생성, 병합의 실제 동작은 확인하지 않았다. 위 표는 확인한 UI와 신규 기획을 구분하며, 기존 서비스의 구현이나 권한 모델을 사실로 추정하지 않는다. 외형·브랜드·이미지는 그대로 복제하지 않는다.

## 3. 문제, 목표, 성공 지표

### 3.1 해결할 문제

- 사진과 의견이 흩어져 있어 장소별 문제와 반복되는 유형을 파악하기 어렵다.
- 시설 유무만으로는 어린이·고령자·휠체어 이용자·유아차 이용자 등의 실제 이용 편의를 알기 어렵다.
- 현장 조사 결과가 기록에 머무르고, 근거 있는 개선 제안으로 이어지기 어렵다.
- 기존 특정 주제 지도는 다른 조사 목적에 맞게 재사용하기 어렵다.

### 3.2 제품 목표

1. 비전문가가 모바일에서 지도 개설과 현장 기록을 완료한다.
2. 주제에 맞는 핀·아이콘·범례로 관찰 분포를 읽고, 편의 평가 주제에서는 세 가지 상태로 편의·불편 분포를 빠르게 읽는다.
3. 누구에게, 언제, 왜 불편했는지를 기록해 개선 아이디어의 근거를 남긴다.
4. 지도마다 조사 주제와 질문을 바꾸면서 같은 도구를 재사용한다.
5. 집계와 원본 기록을 연결해 검토 가능한 제안서를 작성한다.

‘모두에게 편리’는 참여자의 관찰 평가이며 접근성 인증이나 실시간 안전 보장을 의미하지 않는다. 미조사 지역을 편리한 지역으로 표현하지 않는다.

### 3.3 초기 파일럿 성공 지표 — 목표값은 검증 후 조정

| 지표 | 측정 정의 | 초기 목표 |
|---|---|---|
| 지도 개설 성공률 | 개설 시작 대비 유효한 지도 생성 완료 | 80% 이상 |
| 첫 기록 전환율 | 지도에 입장한 고유 참여자 중 1건 이상 제출한 비율 | 60% 이상 |
| 현장 기록 시간 | 위치 선택 시작부터 제출까지, 업로드 포함 | 중앙값 2분 이내 |
| 유효 기록 비율 | 제출 기록 중 관리자가 유지한 유효 기록 | 90% 이상 |
| 제안서 도출률 | 제안 기능이 켜져 있고 유효 기록 10건 이상인 활동 종료 지도 중 제안서 1건 이상 저장 | 50% 이상 |

측정 이벤트는 개설 시작·완료, 입장 완료, 기록 시작·제출, 제안서 저장으로 한정하고 사진·본문·정밀 좌표는 제품 분석 이벤트에 넣지 않는다.

## 4. 사용자와 권한

| 역할 | 주요 권한 |
|---|---|
| 방문자 | 공개 지도와 게시된 기록·공유된 제안서 열람 |
| 참여자 | 참여한 지도에 기록·댓글·제안서 초안 작성, 본인 콘텐츠 수정·삭제 |
| 지도 관리자 | 지도 설정, 초대·참여자 관리, 기록·댓글 검수·숨김, 제안서 확정·공유 |
| 지도 소유자 | 관리자 권한 부여·회수, 지도 공개 전환·보관·삭제 |
| 서비스 운영자 | 신고 처리와 서비스 운영에 필요한 제한된 관리, 접근 이력 기록 |

게스트도 내부 참여자 ID와 서버가 발급한 세션으로 식별한다. 닉네임 자체를 인증 수단이나 수정 권한의 근거로 사용하지 않는다. 기기 변경·세션 삭제 시 본인 기록 수정 권한은 자동 복구되지 않으며 관리자 지원 또는 추후 계정 연결을 사용한다.

각 역할의 기능 사용 권한은 해당 지도에서 활성화된 기능에 한해 적용한다.

### 4.1 열람과 참여 정책

- **공개 지도:** 누구나 읽을 수 있고 탐색에 노출된다. 쓰기는 초대 코드·닉네임으로 입장한 참여자만 가능하며, 개설자가 코드 배포 대상을 정한다.
- **초대 전용 지도:** 유효한 초대 코드·링크로 참여한 사람만 읽고 쓴다. 지도 ID나 URL만 알아서는 열람할 수 없다.
- **참여 범위:** 개설자는 ‘초대받은 참여자 기록 가능 / 관리자만 기록 가능 / 기록 마감’을 열람 공개 범위와 독립적으로 선택한다. 댓글 허용 여부도 별도 설정한다.
- **검수 방식:** 즉시 게시 또는 관리자 승인 후 게시. 학교 활동으로 설정한 지도는 주제와 관계없이 승인 후 게시를 기본으로 한다.
- 초대 코드는 만료·폐기·재발급할 수 있다. 폐기는 신규 입장을 막으며 기존 참여자 제거는 별도 동작이다.
- 공개 전환 시 대상 기록·사진·좌표·제안서의 노출 범위를 미리 확인한다. 미승인 기록은 공개하지 않는다.
- 공유 링크와 QR은 현재 권한을 그대로 따른다. 공유 동작으로 접근 권한이 자동 확대되지 않는다.

### 5.2 후속 버전

- AI 분석·문제 요약·제안서 초안·사람의 검토 피드백.
- 재관찰을 연결하는 개선 전후 비교, 개선 진행 상태 관리.
- 정교한 위치 밀집 분석·다중 지도 비교·지도 병합.
- 정식 PWA 설치와 오프라인 작성·재접속 동기화.
- 자동 얼굴·차량번호 가림, 음성 입력, 다국어, 활동 퀴즈.
- 외부 공공데이터·기상 관측 연동.

첫 출시에서 실시간 위치 추적, 길찾기 알고리즘, 자동 위험 판정, 생물종 자동 확정, 네이티브 앱은 개발 범위에 포함하지 않는다.

## 6. 주제 선택과 기능 구성

**주제는 지도 제목이나 분류 이름에 그치지 않고, 사용할 기능과 화면을 결정하는 설정이다.** 지도 생성 시 주제를 먼저 선택하고 해당 주제의 기능 구성을 복사한다. 지도 안의 ‘분류’는 그 주제에 속한 기록 유형이다. 예를 들어 ‘생태’는 지도 주제, ‘새·곤충·식물’은 기록 분류다.

### 6.1 지도 생성 흐름

1. **주제 선택:** 유니버설 디자인 / 안전 / 생태 / 날씨생활 / 직접 만들기 카드에서 하나를 선택한다. 각 카드에 목적, 예시 핀, 주요 입력항목, 제공 기능을 보여준다.
2. **기본 정보:** 제목·설명·조사 지역을 입력한다.
3. **주제별 설정:** 선택한 주제의 분류·질문·핀 범례·분석·제안 기능을 확인하고 허용된 항목을 편집한다. 기본 설정으로 바로 진행할 수 있다.
4. **참여·공개 설정:** 공개 범위·초대 참여·검수 방식을 선택한다. 학교·일반 커뮤니티 운영 방식은 주제와 독립적으로 선택한다.
5. **미리보기·개설:** 실제 참여자에게 보일 지도·기록 양식·하단 메뉴를 확인하고 개설한다.

생성 중 주제를 바꾸면 제목·설명·지역·권한은 유지하고, 호환되지 않는 주제별 설정의 변경 내용을 안내한 뒤 새 기본값을 적용한다. 입력한 사용자 설정을 조용히 버리지 않는다.

### 6.3 주제별 기능 매트릭스 — 권장 기본값

사용자가 확정한 것은 ‘주제별 차등 적용’이다. 아래 주제별 조합은 기획 권장안이며, 모든 주제에 동일한 3색 평가를 강제하지 않는다.

| 주제 | 기본 핀 표현 | 종합평가 | 주제별 입력 | 분석 | 개선 아이디어·제안서 |
|---|---|---|---|---|---|
| 유니버설 디자인 | 평가 결과 3색 + 시설 아이콘 | 모두에게 편리 / 조금 불편 / 개선 필요 | 이동·정보·소리 안내·휴식·안전 5개 평가 | 상태·시설·평가항목별 분포 | 기본 사용 |

| 생태 | 생물·환경 분류별 색상과 아이콘 | 기본 사용 안 함 | 생물명(모름 허용), 관찰 특징, 서식환경 | 분류·관찰 시기·공간 분포 | 기본 끔, 보전 활동 시 선택 |

날씨생활의 생활 영향 평가는 상세·목록·필터에 표시하며 기본 핀 색은 날씨 유형을 나타낸다. 평가가 존재하는 것과 핀 색을 평가에 사용하는 것은 별도 설정이다. ‘모두에게 편리’ 문구를 생태나 날씨에 일괄 적용하지 않는다.

**공통 기능:** 카카오맵, 참여·권한, 위치·사진·링크·설명·주제별 이모지 포인트 아이콘, 댓글·검수, 지도/목록, 분류·기간 통계. 이모지 포인트 아이콘은 모든 주제에 필수 적용한다. 댓글 등 운영자가 끌 수 있는 공통 기능은 기존 권한 설정을 따른다.

**주제에 따라 달라지는 기능:** 종합평가와 기준, 세부 평가·추가 질문, 핀 색상의 의미, 평가 필터·차트, 개선 아이디어, 제안서 메뉴. 비활성 기능은 입력·상세·메뉴·필터·차트에서 숨기고 필수 입력 검사에서도 제외한다. 제안 기능이 꺼져 있어도 지도·기록·기본 분석은 정상 동작한다.

MVP는 미리 정의한 기능을 설정으로 조합한다. 사용자가 새 프로그램 기능이나 임의 코드를 추가하는 기능 제작기는 범위에 포함하지 않는다.

### 6.4 설정 편집과 변경 규칙

- 권장 초기 상한: 분류 12개, 평가항목 10개. 초과 요구는 실제 파일럿 후 판단한다.
- 분류에는 이름·대표 이모지·선택 가능한 이모지 목록을 지정한다. 분류 색상 모드에서는 색상도 지정하며, 평가 색상 모드에서는 평가 기준의 색상을 사용한다.
- 핀 표현 모드는 평가 색상 / 분류 색상 / 단일 색상 중 하나다. 평가 색상은 종합평가 기능이 켜져 있고 평가 기준이 정의된 경우에만 선택할 수 있다.
- 평가항목에는 이름·아이콘·도움말·응답 유형·필수 여부를 지정한다.
- 지원 응답: 3단계 평가, 예/아니오, 단일 선택, 복수 선택, 짧은 서술.
- 응답 가능한 항목에는 ‘확인 못함’과 ‘해당 없음’을 구분해 제공한다.
- 조사 시작 후 기존 응답이 있는 항목은 삭제 대신 비활성화한다. 응답 의미가 바뀌는 변경은 새 버전으로 생성한다.
- 기록은 제출 당시 질문 버전에 연결한다. 버전 간 집계 시 비교 가능한 항목만 합산한다.
- 기록이 없는 지도는 주제를 변경할 수 있다. 첫 기록 제출 후에는 주제·종합평가 기준·핀 표현 모드를 고정한다. 다른 주제로 조사하려면 새 지도를 만들고 기존 지도는 보존한다.
- 운영 중 질문 추가·비활성화와 제안 기능 켜기·끄기는 가능하다. 기능을 끄더라도 기존 데이터는 삭제하지 않고 관리자 보관 화면에 유지하며, 다시 켜면 복원한다. 설정 변경 시 영향과 이력을 남긴다.

### 6.5 모든 지도에 적용되는 주제별 이모지 아이콘

주제를 선택하면 그 주제와 분류에 맞는 이모지 묶음을 기본 배정한다. 지도 전체가 같은 이모지 하나를 쓰는 방식이 아니라, 포인트의 구체적인 관찰 유형에 맞는 다양한 이모지를 제공한다. 아래 배정은 초기 예시이며 지도 개설자가 주제에 맞게 편집할 수 있다.

| 주제 | 기본 이모지 배정 예시 |
|---|---|
| 유니버설 디자인 | ♿ 이동·접근 시설, 🚪 출입구, 🛗 엘리베이터, 🚻 화장실, 🪑 휴식공간, 🔊 소리 안내 |
| 안전 | 🚦 교통신호, 🚸 어린이 보행, 💡 조명, 🧯 소방시설, 🚧 공사·통행 장애, 🛟 수변 안전 |
| 생태 | 🌳 나무, 🌼 꽃, 🌿 풀, 🐦 새, 🦋 나비, 🐞 곤충, 🐸 양서류, 💧 물·습지 |
| 날씨생활 | ☀️ 햇빛·더위, 🌧️ 비, 💧 물고임, 💨 강풍, 🧊 빙판, 😷 미세먼지, 🌳 그늘 |
| 직접 만들기 | 개설자가 주제에 맞는 분류별 이모지를 지정. 예: 독서 지도 📚·📖, 문화 지도 🎨·🎭·🏛️ |

- **개설 시:** 주제별 추천 이모지와 텍스트 의미를 함께 보여준다. 각 활성 분류에 대표 이모지 하나와 선택 가능한 목록을 배정한다. 직접 만들기도 모든 분류의 대표 이모지를 지정해야 개설할 수 있다.
- **등록 시:** 참여자가 분류를 선택하면 대표 이모지를 자동 선택한다. 같은 분류에 배정된 다른 이모지로 바꿀 수 있고, 선택을 생략하면 대표 이모지를 사용한다. 분류를 변경하면 새 분류의 대표 이모지로 갱신하고 미리보기에 반영한다.
- **표시 시:** 개별 핀 중앙에 이모지 하나를 표시하고, 목록·상세·등록 미리보기에도 동일한 이모지와 의미를 사용한다. 평가 기호는 별도 배지로 표시하여 이모지를 대체하지 않는다.
- **색상과 역할 구분:** 이모지는 ‘무엇을 관찰했는가’, 핀 배경색은 해당 지도의 평가 또는 분류를 나타낸다. 예를 들어 ♿는 이동·접근 시설이라는 유형이며 그 자체로 ‘모두에게 편리’를 의미하지 않는다.
- **군집:** 여러 포인트가 묶이면 총건수를 우선 표시한다. 군집 선택 목록과 확대 후 개별 핀에서 각각의 이모지를 확인할 수 있어야 한다. 서로 다른 관찰을 하나의 대표 이모지로 잘못 단정하지 않는다.
- **저장·검증:** 포인트에 선택한 이모지 항목 ID를 저장하고 서버는 해당 지도·분류에 허용된 항목인지 검증한다. 사용 중인 이모지의 그림이나 의미를 바꾸려면 새 항목을 만든다. 기존 항목은 비활성화해 신규 선택만 막고 기존 기록의 표현은 보존한다.
- **접근성·기기 대응:** 이모지마다 ‘나무’, ‘휴식공간’ 같은 이름을 제공한다. 이모지 모양이 기기별로 달라도 뜻을 알 수 있도록 텍스트를 함께 사용한다. 지원되지 않는 이모지는 대체 표시와 의미 텍스트를 제공하며 핀을 비워두지 않는다. 조합형 이모지도 하나의 선택 항목으로 처리한다.

## 7. 지도와 주제별 핀 표현

### 7.1 유니버설 디자인의 3색 종합평가

아래 표는 유니버설 디자인 등 이 평가 기준을 선택한 지도에만 적용한다.

| 값 | 표시 문구 | 권장 색상 | 상태 보조 기호 | 판단 기준 |
|---|---|---|---|---|
| comfortable | 모두에게 편리 | 초록 #16803D | ✓ | 조사한 이용 상황에서 편리함을 확인 |
| inconvenient | 조금 불편 | 주황 #B85C00 | ! | 이용할 수 있지만 불편하거나 일부 보완 필요 |
| needs_improvement | 개선 필요 | 빨강 #C62828 | × | 이용 장벽·위험·환경 문제가 있어 개선 제안 필요 |

색상은 디자인 후보이며 실제 배경·크기에서 대비를 검증한다. 이 평가 기준 안에서는 세 가지 상태 이름을 유지한다. 안전·날씨생활은 각 주제의 평가 기준을 사용하고 생태 기본형은 종합평가를 요구하지 않는다. 평가형 지도에서는 조사자가 근거를 작성하고 상태를 선택하며, 항목 점수의 단순 평균으로 자동 결정하지 않는다.

**평가 색상 모드에서는 색이 판단 결과를, 분류 색상 모드에서는 색이 기록 유형을 나타낸다.** 모든 개별 핀 중앙에는 주제·관찰 유형에 맞는 이모지를 표시한다. 평가 기호는 평가 모드에서 별도 배지로 사용한다. 단일 색상 모드에서도 다양한 이모지·텍스트로 관찰 유형을 구분한다. 범례에 색상과 이모지의 의미를 명시하며 색만으로 정보를 전달하지 않는다. 현재 위치는 핀과 구분되는 파란 점, 선택한 포인트는 테두리 강조로 나타낸다.

### 7.2 지도 동작

- 최초에는 지도 개설자가 지정한 조사 지역을 표시한다. 위치 권한 요청은 ‘내 위치’ 또는 기록 위치 지정 때 한다.
- 핀 탭 시 상세 요약 바텀시트가 열리고, 목록 카드 선택 시 해당 핀으로 이동한다.
- 밀집 구역은 총건수 군집으로 표시한다. 평가 색상 모드는 평가별 분포, 분류 색상 모드는 분류별 분포를 함께 제공한다. 평균색 하나로 위험 기록을 가리지 않으며, 평가가 없는 지도에 위험 분포를 생성하지 않는다.
- 군집 탭 시 확대하고, 같은 좌표의 여러 기록은 선택 목록으로 제공한다.
- 화면 하단에 현재 핀 모드에 맞는 건수·범례를 표시한다. 예: 편의 평가 ‘편리 12 · 불편 8 · 개선 5’, 생태 ‘식물 12 · 새 8 · 곤충 5’.
- 현재 화면 내 검색과 지도 전체 검색을 명시적으로 구분한다. 지도 이동 후 ‘이 지역에서 보기’를 누르면 화면 범위를 결과 조건에 반영한다.
- 포인트가 없는 지역은 ‘아직 조사 기록이 없습니다’로 표시한다.
- 지도 위에 표시하는 점은 관찰 기록 단위다. 동일 장소의 다른 시점·참여자 기록을 자동 병합하지 않는다.
- 카카오맵 출처·저작권 표시를 가리지 않는다.

## 8. 포인트 등록과 상세

### 8.1 등록 흐름: 3단계

1. **위치와 사진:** 현재 위치 또는 주소·장소 검색 → 핀 수동 조정 → 위치 확정 → 촬영·앨범 선택.
2. **관찰 내용:** 제목·분류·설명 → 주제별 질문. 평가 기능이 켜져 있으면 종합평가·평가항목·판단 근거를 추가한다.
3. **추가 정보와 확인:** 관련 링크 → 개선 아이디어(활성 지도만) → 미리보기 → 공개 범위·사진 점검 → 제출.

단계 간 이동 시 입력을 유지하고, 오류는 해당 입력 바로 아래에 표시한다. 같은 기기의 텍스트 초안 복구를 제공하되 파일이 복구되지 않는 경우 사진 재선택을 명시한다. 전송 실패는 입력을 유지하고 재시도를 제공하며, 서버는 중복 제출을 방지한다.

### 8.2 데이터 입력 명세 — 수치는 초기 권장 제한

| 항목 | 필수 여부 | 요구사항 |
|---|---|---|
| 지도 ID·작성자 ID | 자동 | 서버에서 권한 검증 |
| 제목 | 필수 | 2~60자 |
| 위치 | 필수 | WGS84 좌표, 주소 또는 장소명, GPS/검색/수동 선택 경로 |
| 위치 정확도 | GPS 시 자동 | 가능한 경우 정확도(m) 기록, 낮은 정확도에서는 수동 확인 안내 |
| 관찰 시각 | 필수 | 현재 시각 기본값, 과거 관찰 시 수정 가능, 제출 시각 별도 저장 |
| 대표 분류 | 필수 | 지도에 정의된 분류 하나 선택 |
| 포인트 이모지 | 모든 주제에서 필수·자동 기본값 | 분류의 대표 이모지를 자동 배정, 허용 목록에서 변경 가능. 핀·목록·상세에 동일하게 표시 |
| 종합평가 | 기능 사용 시 필수 | 해당 지도의 평가 기준 중 하나, 비활성 지도에서는 입력·저장 요구 없음 |
| 관찰 내용 | 필수 | 10~2,000자, 일반형은 ‘무엇을 관찰했나요?’, 평가형은 판단 근거도 안내 |
| 평가항목 응답 | 지도 설정 | 필수 항목은 미응답 방지, 확인 못함·해당 없음 허용 |
| 사진 | 기본 선택 | 최대 5장, 원본 장당 10MB, 지도 관리자가 1장 이상 필수 설정 가능 |
| 사진 설명 | 사진 첨부 시 | 이미지에서 관찰할 사항을 짧게 설명, 접근성 대체 텍스트에 활용 |
| 관련 링크 | 선택 | 최대 3개, HTTP(S) 주소와 표시 제목 |
| 개선 아이디어 | 기능 사용 시 선택 | 최대 1,000자, 개선을 요구하는 평가 선택 시 입력 안내 |
| 영향받는 이용 상황 | 관련 주제에서 선택 | 휠체어·유아차·어린이·고령자·시각/청각 정보 이용 등 복수 선택 |
| 템플릿 추가 질문 | 설정에 따름 | 안전 이유·날씨 유형·생태 관찰 특성 등 |

이용 상황은 장소의 조건을 설명하는 값이다. 작성자 자신의 장애·건강 상태를 요구하지 않는다. 미세먼지 등은 관찰과 출처가 있는 측정값을 구분하며, 사진만으로 측정 사실을 확정하지 않는다.

사진은 업로드 전에 크기를 줄이고 방향을 보정하며, EXIF 위치 등 불필요한 메타데이터를 제거한다. 서버에서 파일 형식·크기·내용을 검사한다. JPEG·PNG·WebP를 우선 지원하고 HEIC는 변환 지원 여부를 구현 검증 후 확정한다. 지원하지 않는 형식은 변환 방법을 안내한다.

### 8.3 유니버설 디자인 주제의 평가항목 기본 예시

| 아이콘 의미 | 항목 | 질문 | 응답 |
|---|---|---|---|
| 이동·경사로 | 이동편의성 | 계단·폭·경사·장애물 때문에 이동이 어렵나요? | 편리/조금 불편/개선 필요/확인 못함/해당 없음 |
| 정보·안내판 | 정보 접근성 | 안내를 찾고 읽거나 이해하기 쉬운가요? | 같은 3단계 + 확인 못함/해당 없음 |
| 스피커 | 소리 안내 여부 | 필요한 장소에 작동하는 소리 안내가 있나요? | 있음/없음/확인 못함/해당 없음 |
| 벤치 | 휴식공간 여부 | 잠시 앉아 쉬거나 더위·비를 피할 공간이 있나요? | 있음/없음/확인 못함/해당 없음 |
| 방패 | 안전성 | 충돌·낙상·차량 등 이용 중 위험 요소가 있나요? | 같은 3단계 + 확인 못함/해당 없음 |

‘없음’이 항상 개선 필요라는 뜻은 아니다. 소리 안내가 필요 없는 장소처럼 상황에 따라 해석하며, 종합평가에는 판단 근거를 남긴다.

### 8.4 상세 화면과 댓글

- 사진 갤러리 → 제목·분류 → 장소·관찰 시각 → 관찰 내용·주제별 질문 → 관련 링크 → 댓글 순서로 구성한다. 평가·개선 아이디어 기능이 켜진 지도에는 해당 블록을 추가한다.
- 닉네임과 작성·수정 시각을 표시하고 작성자의 실시간 위치는 표시하지 않는다.
- 댓글은 참여자만 작성하며 기본 최대 500자, 본인 수정·삭제와 신고를 제공한다. MVP는 평면 댓글로 시작한다.
- 타인의 기록 본문은 참여자가 수정할 수 없다. 관리자는 숨김·복구·수정 요청을 통해 검수하고, 직접 수정이 필요하면 변경 이력을 남긴다.
- 삭제·숨김 기록은 일반 조회와 집계에서 즉시 제외한다. 관리자 복구 가능 기간은 운영 정책에서 확정한다.
- 승인된 기록을 수정하면 승인형 지도에서는 재검수하며, 재승인 전에는 공개 결과에서 제외한다.

## 9. 분석과 개선 제안

### 9.1 기본 분석

- 공통 분석: 총 기록 수, 유형별 건수, 기간별 기록 추이.
- 평가 기능 사용 시: 해당 평가 기준별 건수·비율과 항목별 응답 분포, ‘확인 못함’·‘해당 없음’ 건수.
- 주제별 분석: 안전의 위험 유형, 생태의 생물·환경 분류, 날씨의 유형·생활 영향 등 활성 질문에 맞는 차트와 원본 기록 목록.
- 지도상의 분포와 목록을 연결하고, 차트 항목 선택 시 해당 기록으로 필터링.
- 관리자용 CSV에는 승인 상태·질문 버전·관찰 시각 등 분석에 필요한 메타데이터 포함. 작성자 정보·정밀 좌표의 내보내기는 권한 및 선택 옵션으로 제한.

**집계 규칙:**

1. 기본 집계는 현재 사용자가 열람할 수 있는 게시 기록만 포함한다. 검수 대기·숨김·삭제·초안은 제외한다.
2. 지도·목록·차트는 같은 필터와 지역 범위를 사용하고, 활성 조건을 화면에 표시한다.
3. 종합평가 비율은 해당 평가 기준에 유효하게 응답한 기록 수가 분모다. 평가항목 비율도 해당 항목의 유효 응답 수가 분모이며 제외 수를 함께 표시한다. 평가가 없는 지도는 평가 차트를 생성하지 않고, 평가 미사용을 ‘편리’나 0점으로 환산하지 않는다.
4. 같은 장소에 여러 관찰이 있으면 여러 건으로 센다. ‘기록 20건’을 ‘서로 다른 시설 20곳’으로 바꾸어 표현하지 않는다.
5. 기록 수가 많은 구역은 관찰 활동이 많았을 가능성도 있다. 표본 수·기간·관찰 범위를 함께 표시하며, 조사하지 않은 동네까지 점수를 확대 해석하지 않는다.
6. 군집은 지도 표시용 묶음이고 행정구역 통계가 아니다. MVP 지역 분석은 조사 지역과 화면 범위 중심이며 정식 행정구역·격자 분석은 후속이다.

### 9.2 개선 제안서

제안 기능이 활성화된 지도에서 제공한다. 제안서는 지도 안에 저장하는 별도 문서이며, 참여자 초안 작성 후 관리자가 확정·공유한다. 생태 지도도 보전 활동을 위해 제안 기능만 켤 수 있으며 종합평가를 요구하지 않는다.

| 필드 | 내용 |
|---|---|
| 제목 | 예: 학교 앞 횡단보도 시야 개선 제안 |
| 발견한 문제 | 어떤 장소에서 누구에게 어떤 불편이 발생하는가 |
| 데이터 근거 | 연결한 포인트, 필터 조건, 조사 기간, 관련 건수·사진 |
| 개선 제안 | 실제로 바꾸려는 시설·안내·운영 방식 |
| 기대 효과 | 이용 편의·안전·환경 측면의 개선 |
| 실천 주체 | 학생·주민·학교·시설 관리자 등 제안 대상 |
| 후속 확인 계획 | 재관찰 시기와 확인할 항목 |

저장 시 근거 포인트 ID, 집계 조건, 집계 시각, 당시 수치를 스냅샷으로 보관한다. 원본 수정·삭제 후에는 ‘근거 변경됨’ 표시와 재검토를 제공한다. 삭제된 개인정보·사진을 스냅샷에 복제 보존하지 않는다. 공유본은 열람 권한이 있는 근거만 노출하며, 새 버전 확정 전 기존 확정본을 자동 덮어쓰지 않는다.

MVP는 웹 제안서·공유 링크·인쇄 레이아웃을 제공한다. PDF는 브라우저의 PDF 저장을 우선 사용하며, 카카오 지도 화면의 이미지 저장·문서 삽입은 허용 범위 확인 후 별도로 결정한다. 초기 인쇄본에는 자체 통계와 허용된 사진, 지도 연결 링크·QR을 사용한다.

### 9.3 AI 분석 — 후속 요구사항

- 관리자가 요청한 지도·기간·필터의 허용된 기록만 분석한다.
- 반복 문제·밀집 양상·개선 제안 초안을 생성하며 근거 포인트와 표본 수를 표시한다.
- 수치 집계는 서버가 계산한 결과를 사용하고, AI가 임의의 통계나 사실을 만들지 않도록 한다.
- 사용자는 ‘맞아요 / 조금 달라요 / 잘 모르겠어요’로 검토하고 설명을 남긴다.
- AI 결과는 초안 상태로 저장하며 관리자가 검토 후 확정한다. 자동 공개·민원 제출을 하지 않는다.
- 데이터 부족·오류·시간 초과는 표시하고 기본 통계와 수동 제안서 작성은 계속 제공한다.
- AI 제공자, 비용 상한, 전송 필드, 보관 정책은 도입 전에 확정한다. 기본 전송에서는 닉네임·사진·정밀 좌표를 제외하고 최소 정보로 분석한다.

## 10. 모바일 정보 구조와 화면 규격

### 10.1 전체 정보 구조

```text
홈: 내 지도 / 공개 지도 / 지도 검색 / 초대 코드 / 새 지도
 ├─ 지도 생성: 주제 선택 → 기본 정보 → 주제별 설정 → 참여·공개 → 미리보기
 └─ 개별 지도
     ├─ 지도: 핀 / 목록 / 검색 / 필터 / 범례 / 내 위치
     │   └─ 포인트 상세: 사진 / 관찰 내용 / 주제별 항목 / 링크 / 댓글
     ├─ 기록: 위치·사진 → 관찰 내용·주제별 질문 → 추가 정보·확인
     ├─ 분석: 공통 통계 / 주제별 차트 / 원본 기록
     ├─ 제안(활성 시): 목록 / 초안 작성 / 확정본 / 공유
     └─ 더보기: 지도 소개 / 참여자 / 초대 / 설정 / 내 기록
```

### 10.2 기준 화면과 비율

- 모바일 기준 너비 390 CSS px, 필수 대응 범위 360~430 px. 320 px에서도 주요 기능에 가로 스크롤이 생기지 않도록 한다.
- 세로 높이는 기기마다 달라지므로 고정 종횡비를 강제하지 않는다. 동적 뷰포트 높이와 상·하단 안전 영역을 반영한다.
- 지도 화면 기본 상태: 헤더 약 56px, 검색·필터 약 88px, 하단 내비게이션 약 64px+안전 영역, 나머지에 지도를 배치한다.
- 390×844 기준으로 지도 영역이 약 60~70%를 차지하도록 검증한다. 하단 요약 카드가 열리면 실제로 보이는 지도 면적은 줄어든다.
- 바텀시트는 가용 높이의 약 20% / 50% / 90% 세 단계. 드래그 외에 ‘자세히·접기’ 버튼도 제공한다.
- 입력 화면은 전체 높이를 사용하고 하단에 이전·다음 또는 등록 버튼을 고정한다. 키보드가 입력칸과 버튼을 가리지 않게 스크롤한다.
- 본문 16px 이상, 핵심 버튼·터치 영역 최소 44×44px를 제품 기준으로 적용한다.
- 사진 미리보기는 4:3을 기본으로 하고 원본 전체 보기 지원. 사진 비율 때문에 필수 입력이 과도하게 밀리지 않게 한다.
- 768px 이상은 지도와 상세 패널 병렬 배치를 허용하되 모바일과 기능·권한이 동일하다.

### 10.3 지도 화면 와이어프레임

아래는 유니버설 디자인 주제의 예시다. 생태 지도에서는 필터·범례를 ‘식물 / 새 / 곤충 …’으로 바꾸고, 기본 하단 메뉴를 ‘지도 / 기록 / 분석 / 더보기’로 구성한다. 제안 기능을 켜면 제안 메뉴를 추가한다. 숨긴 기능의 빈 자리나 비활성 탭을 남기지 않는다.

```text
┌──────────────────────────────┐
│ ‹  우리 동네 모두의 길    공유 │  지도 제목·나가기
├──────────────────────────────┤
│ 장소·기록 검색           목록 │
│ 전체  편리  불편  개선  필터  │  한 줄 스크롤 칩
├──────────────────────────────┤
│                              │
│        카카오 지도           │
│   ♿초록   🚪주황   🪑빨강    │  중앙 이모지 + 별도 평가 배지
│                      내 위치 │
│                              │
│  25건 · 편리12 불편8 개선5    │  범례·결과 요약
├──────────────────────────────┤
│ 지도  기록＋  분석  제안  더보기│  하단 메뉴
└──────────────────────────────┘
```

기록 버튼은 하단 중앙 근처에서 강조한다. 지도 조작 버튼·바텀시트·카카오맵 출처가 서로 겹치지 않아야 한다. 지도 핀과 목록은 같은 선택 상태를 유지한다.

## 11. 주요 사용자 시나리오

### A. 교사 또는 주민 모임 운영자가 조사 지도를 만든다

로그인 → 새 지도 → 유니버설 디자인 템플릿 → ‘우리 동네 모두의 길’ 제목 → 조사 지역 설정 → 기본 5개 평가항목 확인 → 초대 전용·승인 후 게시 → 지도 생성 → 초대 링크·QR 배포.

### B. 참여자가 보행로를 기록한다

초대 링크 → 조사 기준 확인 → 닉네임 입장 → 기록 → 위치 허용 또는 수동 검색 → 사진 → ‘보행로’ 선택 → ‘개선 필요’ → 이동편의성·안전성 평가 → ‘턱 때문에 유아차가 돌아가야 함’ 근거 → ‘경사로 연결’ 아이디어 → 제출 → 내 기록에 승인 대기 표시.

### C. 참여자들이 분석하고 개선을 제안한다

게시된 기록 25건 → ‘개선 필요’ 필터 → 보행로 관련 5건 확인 → 근거 포인트 선택 → 제안서 초안 → 관리자가 검토·확정 → 지도 권한 범위 내 공유.

### D. 날씨생활 4차시 활동

1차시에는 더위·물고임·바람·빙판 등 관찰 지점을 찾는다. 2차시에는 사진·위치·날씨 유형·판단 근거를 기록한다. 3차시에는 유형별 건수와 분포를 비교한다. 4차시에는 그늘 쉼터·배수 개선·주의 안내 등의 행동을 제안한다. 동일한 흐름은 생태와 안전 주제에도 재사용한다.

### E. 생태 관찰 지도를 만든다

새 지도 → 생태 선택 → 식물·새·곤충 분류 및 분류별 핀 미리보기 → 개설·초대 → 위치·사진·분류·생물명·관찰 특징 입력 → 종합평가 없이 등록 → 분류·기간별 분포 확인. 편리·불편·개선 입력과 필터는 나타나지 않는다. 추후 보전 제안을 하려면 관리자가 제안 기능을 켠다.

지도는 생성 당시 템플릿 설정을 복사해 보관하므로 템플릿 업데이트가 기존 지도에 자동 적용되지 않는다. 핀·양식·필터·분석은 같은 지도 설정을 읽는다. 서버도 활성 기능과 질문 버전을 기준으로 입력을 검증하며, 비활성 필드에 대한 쓰기는 거부한다. 평가값이 없는 기록에 기본 평가를 채우지 않고 서로 다른 주제의 평가를 같은 척도로 집계하지 않는다. CSV도 주제에 맞는 열과 평가 기준 정보를 제공한다.

관찰 기록·사진·댓글은 지도 권한을 따른다. 데이터베이스 조회, API, 파일 접근, 내보내기에서 동일한 권한 검사를 적용한다. 다른 지도 ID를 대입해 접근할 수 없어야 한다.

상태 흐름:

- 지도: 초안 → 운영 중 → 보관. 보관 시 열람은 유지하고 신규 기록·댓글·제안 작성을 중지한다. 관리자 검수·복구는 가능하다.
- 기록: 초안 → 제출 → 승인 대기 또는 게시 → 숨김/삭제. 승인 대기는 작성자·관리자만 볼 수 있다.
- 제안서: 초안 → 검토 요청 → 확정 → 보관. 확정 후 변경은 새 버전으로 관리한다.

## 13. 카카오맵·위치 기술 요구사항

카카오 지도 JavaScript SDK를 사용한다. 공식 가이드는 JavaScript 키와 이용 도메인 등록, 장소 검색·주소 변환용 `services`, 마커 군집용 `clusterer` 라이브러리를 안내한다. 개발·검증·운영 도메인을 각각 등록하고 실제 앱 설정에서 동작을 검증한다. [카카오맵 Web 가이드](https://apis.map.kakao.com/web/guide/)

- GPS는 브라우저 위치 기능을 통해 동의 시 단발성으로 얻는다. 지도 API가 사용자 위치를 자동 제공한다고 가정하지 않는다.
- 현재 위치는 브라우저에서 지도 이동과 기록 위치 후보 지정에 사용하고, 사용자가 확정한 관찰 좌표만 저장한다.
- HTTPS를 기본으로 한다. 위치 권한 거부·시간 초과·낮은 정확도에서도 주소 검색·수동 위치 지정을 제공한다.
- 지도 크기·바텀시트·가로세로 전환에 맞춰 지도 표시를 재계산한다.
- API 키별 허용 도메인과 제한을 관리한다. 공개 클라이언트 키와 서버 전용 비밀키를 구분하고, 서버 비밀키는 브라우저에 배포하지 않는다.
- 카카오맵 로딩 실패 시 기록 목록·기존 자료 열람은 유지한다. 유효한 위치를 정하지 못한 새 기록은 초안으로 보관하고 재시도를 안내한다.
- 장소 검색 호출을 지연·취소하고, 현재 영역·확대 수준에 맞춰 포인트를 조회한다. 대량 포인트 전체를 매번 내려받지 않는다.
- 초기 시험 데이터는 지도당 5,000건, 동시 사용자 100명을 기준으로 한다. 화면별 응답량과 군집 처리 방식을 검증 후 확정한다.
- 사용량·쿼터 오류를 모니터링하고 운영 알림을 제공한다. 무료량·단가를 기획서에 고정하지 않으며 출시 시 앱에 적용되는 조건을 확인한다. [카카오 쿼터 문서](https://developers.kakao.com/docs/ko/getting-started/quota)

회원·권한·기록 API, 공간 조회가 가능한 데이터베이스, 사진 저장소, 집계 기능을 구성 요소로 둔다. 구체적 프레임워크와 클라우드는 팀 역량·예산·호스팅 조건을 확인한 뒤 기술 설계에서 확정한다.

## 14. 개인정보·운영·접근성 요구사항

- 얼굴·차량번호·주소 등 불필요한 개인정보가 포함되지 않도록 촬영·제출 화면에서 안내한다. MVP에서는 재촬영·사진 제외·관리자 검수가 가능해야 하며 자동 가림을 제공한다고 표시하지 않는다.
- 거주지·아동 생활 동선·민감한 생태 위치는 공개 전에 검토한다. 공개에서 제외한 기록은 핀뿐 아니라 댓글·검색·통계·첨부에서도 노출하지 않는다.
- 공개 제외가 필요한 정밀 위치를 MVP에서 임의로 흐리게 표시하는 기능은 제공하지 않는다. 해당 기록을 비공개 지도에 유지하거나 게시에서 제외한다. 별도 좌표 일반화 기능은 후속 설계한다.
- 업로드 파일은 서버 검사 후 제공하고, 비공개 사진은 추측 가능한 공개 주소로 노출하지 않는다.
- 본문·댓글에 실행 가능한 HTML을 허용하지 않고 링크 프로토콜을 검증한다. 외부 링크 미리보기 자동 수집은 MVP에서 생략한다.
- 로그인·초대·등록·댓글·신고에 요청 제한을 두고 신고·차단·감사 이력을 제공한다.
- 지도·기록 삭제, 게스트 세션 만료, 첨부 정리, 백업 보관·파기 기한은 출시 전 운영 정책으로 확정한다.
- 아동 이용과 위치정보·개인정보 처리에 필요한 동의 및 보호 절차는 서비스 운영 형태에 맞춰 출시 전에 별도 검토한다. 본 문서는 법적 의무 충족을 확인한 문서가 아니다.
- 지도와 동일한 정보를 목록으로 제공한다. 색상 외 텍스트·기호를 사용하고 모든 포인트 이모지와 평가 아이콘에 읽을 수 있는 이름을 둔다.
- 키보드 초점 이동, 스크린리더 레이블, 바텀시트 닫기, 확대 글자, 오류 메시지 연결을 검증한다.
- 끌기 동작만으로 위치를 정하도록 강제하지 않는다. 주소 검색·지도 중앙 위치 확정 버튼을 제공한다.

## 16. MVP 인수 기준

1. 생성 첫 화면에서 주제를 선택하고 실제 핀·양식·기능을 미리볼 수 있다. 안전과 직접 만든 주제의 분류·평가항목은 서로 섞이지 않는다.
2. 초대받은 다른 기기에서 참여해 위치포인트를 등록하면 같은 지도의 관리자에게 표시된다.
3. 모든 주제에서 사진·링크·설명·주제에 맞는 포인트 이모지가 저장된다. 유니버설 디자인에서는 5개 기본 평가항목·개선 아이디어도 상세 화면에서 재확인된다.
4. 유니버설 디자인의 세 종합평가는 지정된 색·기호·문구로 표시된다. 생태의 분류 색상은 평가 상태로 해석되지 않는다.
5. 같은 좌표에 여러 기록이 있어도 모든 기록을 선택·조회할 수 있다.
6. 위치 권한을 거부해도 주소 검색과 수동 위치 확정으로 등록할 수 있다.
7. 승인형 지도에서 대기 기록은 작성자·관리자만 열람하고, 승인 후 지도·목록·통계에 반영된다.
8. 주제에서 활성화된 평가·유형·기간·화면 범위를 필터링하면 지도·목록·차트의 결과 건수가 동일하다.
9. 확인 못함·해당 없음이 평가 비율에서 제외되고 제외 건수와 실제 분모가 표시된다.
10. 다른 참여자는 타인의 기록을 수정·삭제하지 못하며, 닉네임을 동일하게 입력해도 권한을 얻지 못한다.
11. 비공개 지도는 직접 URL·첨부 주소·내보내기 요청으로도 비참여자가 접근할 수 없다.
12. 댓글 작성·본인 수정·삭제·신고와 관리자 숨김이 작동하며, 숨긴 댓글은 일반 사용자에게 노출되지 않는다.
13. 근거 포인트와 집계값을 연결한 제안서를 저장·확정·공유하고, 권한 없는 열람자는 비공개 근거를 볼 수 없다.
14. 사진 업로드 실패·요청 응답 유실 후 재시도해도 본문이 사라지거나 동일 기록이 중복 생성되지 않는다.
15. 360×800, 390×844, 430×932 화면에서 주요 조작과 지도 출처가 겹치지 않고 키보드가 필수 입력·제출 버튼을 가리지 않는다.
16. 색 구분 없이 목록과 분류명·평가 문구로 판단할 수 있고, 스크린리더로 핵심 흐름을 완료할 수 있다.
17. 기록 숨김·삭제·재검수 시 일반 지도·목록·집계에서 제외되며 연결 제안서에는 근거 변경 안내가 나타난다.
18. 네 기본 주제에서 기록·기본 분석을 완료하며, 제안 기능이 켜진 지도에서는 제안서까지 완료할 수 있다.
19. 생태 기본형은 종합평가 없이 제출되며, 평가 입력·평가 필터·편의 비율 차트·제안 메뉴가 나타나지 않는다. 서버에서도 평가 미사용을 허용하고 평가값을 자동 생성하지 않는다.
20. 날씨생활 기본형에서 핀 색은 날씨 유형, 생활 영향 평가는 상세·필터·분석에 표시되어 두 의미가 혼동되지 않는다.
21. 직접 만들기에서 평가 없이 단일/분류 색상 지도를 개설할 수 있다. 평가 색상을 고르면 평가 기준 설정이 필수다.
22. 첫 기록 제출 후 주제·평가 기준·핀 모드 변경이 차단된다. 템플릿 업데이트가 기존 지도와 기록을 바꾸지 않는다.
23. 제안 기능을 끄면 관련 메뉴·쓰기 API가 비활성화되고 기존 자료는 관리자 보관 화면에 남는다. 다시 켜면 기존 자료가 복원된다.
24. 네 기본 주제와 직접 만든 지도 모두에서 다양한 주제별 이모지를 배정할 수 있고, 평가 미사용·단일 색상 지도에서도 각 포인트에 이모지가 표시된다.
25. 분류 선택 시 대표 이모지가 자동 선택되고, 허용된 다른 이모지로 변경·저장하면 핀·목록·상세·미리보기에 일치하게 나타난다. 다른 지도·분류의 이모지 ID를 제출하면 서버에서 거부한다.
26. 이모지 항목을 비활성화해도 기존 기록의 이모지·의미는 보존된다. 스크린리더와 이모지 미지원 환경에서도 의미 텍스트를 확인할 수 있다.

## 17. 출시 단계와 의존성

상세 작업·완료 기준·권장 모델은 [개발 단계와 모델 사용 계획](DEVELOPMENT_PLAN.md)에 정의한다. 개발 단계 번호는 해당 문서와 동일하게 관리한다.

| 단계 | 주요 산출물 | 권장 개발 모델 |
|---|---|---|
| 0. 요구사항 작성 — 완료 | PRD 1.3 | 기존 작업 완료 |

| 2. 모바일 UX와 화면 골격 — 다음 | 주제별 모바일 흐름·샘플 화면 | GPT-6 Sol / High |
| 3. 계정·지도·참여 기반 | 로그인·초대·권한·주제 설정 | GPT-6 Sol / High, 권한 검토 Astra |

| 7. 통합 검증·파일럿 준비 | 인수 기준·접근성·권한·성능 검증 | GPT-6 Astra / High |

각 다음 단계에 착수하기 전에 작업 범위, 권장 모델·추론 수준, 추천 이유, 완료 기준을 사용자에게 먼저 알린다. 단순 문구·이모지 목록 정리에는 GPT-6 Luna / Medium을 보조 선택지로 권장한다. 이 배정은 프로젝트 작업 성격에 따른 권장안이며 실제 모델 전환 여부와 구분한다.

개발 일정과 예산은 개발 인원·기술 환경·AI 포함 여부가 확인된 뒤 산정한다. 카카오 개발자 앱·도메인·운영 호스팅·사진 저장소·개설자 인증 방식 준비가 선행되어야 한다.

## 18. 결정 기록과 후속 확인 사항

2026-09-27 사용자 답변과 정정으로 아래 항목을 확정했다.

1. 학교와 일반 커뮤니티를 모두 대상으로 하며 지도마다 공개·참여 범위를 선택한다.
2. 지도 개설자는 로그인하고 참여자는 초대 코드·닉네임으로 입장한다.
3. 기본 통계·차트·수동 제안서를 먼저 제공하고 AI 분석은 후속 버전으로 둔다.
4. 편의 평가용 3색 핀은 특정 주제에만 적용하며 모든 주제에 강제하지 않는다.
5. 지도 생성의 첫 단계에서 주제를 선택하며, 선택에 따라 입력·핀·분석 등 기능이 달라진다. 구체적인 주제별 기본 조합은 6.3의 권장안으로 관리한다.
6. 모든 지도에 주제에 맞는 다양한 이모지를 배정하고 위치포인트 아이콘으로 사용한다. 이는 핀 색상이나 평가 기능과 독립적인 공통 필수 기능이다.
7. 개발을 단계로 나누고, 다음 단계에 들어가기 전에 작업 성격에 맞는 GPT 모델을 미리 안내한다. 단계별 계획은 DEVELOPMENT_PLAN.md에 유지한다.

8. 1단계 추가 답변: 지도 개설자는 Google 로그인, 개발 구성은 Next.js + Supabase(PostgreSQL·인증·사진 저장)를 사용한다. 기존 서버 환경은 없다.

1단계 기술 결정과 구체화된 운영 규칙은 [기술 설계서](TECHNICAL_DESIGN.md), [데이터 스키마](DATA_MODEL.md), [권한표](PERMISSIONS.md), [API 계약](API_CONTRACT.md)에 정리했다. 예를 들어 미제출 초안은 작성자만 열람하고 관리자 검수는 제출 이후부터 적용한다. 이 단계의 논리 설계 완료는 실제 DB·API 동작 검증 완료와 구분한다.

후속 확인 사항: 서비스명, 목표 출시 시점·예산·개발 인원, 예상 지도·참여자 규모, 학교 조직 관리 필요성, 데이터 보관·삭제 기한. 사진 필수 여부와 관리자 승인 방식은 지도별 설정으로 제공하고 본문의 권장 기본값을 사용한다.
