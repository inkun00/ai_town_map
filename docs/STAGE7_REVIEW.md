# 7단계 — 통합 검증·파일럿 준비

검토일: 2026-09-29. 상태: 자동 검사·브라우저 검증 및 주요 결함 수정 완료, 실기기 검증과 일부 인수 기준 미충족. **전체 인수 완료나 정식 출시 승인으로 간주하지 않는다.**

## 이번 변경

- 같은 위치의 기록을 좌표 소수점 6자리 기준으로 묶고, 핀을 누르면 모든 기록의 이모지·제목을 선택할 수 있게 했다. 필터에서 제외된 기록은 선택 목록에서도 제외한다.
- 카카오 지도 내부 레이어에 가려지던 범례와 새 기록 버튼의 표시 순서를 수정했다. 지도 출처 표시 영역은 남겨 둔다.
- GPS의 예상 오차를 표시하고 ‘이 위치 사용’으로 확인한다. 검색·수동 선택 이후 도착한 오래된 위치 요청 결과는 무시한다. 실기기 GPS 검증은 별도다.
- 상세 창을 네이티브 모달로 바꾸고 Escape 닫기·키보드 초점 제어를 적용했다. 목록에서 열면 목록을 유지하고, 닫을 때 원래 버튼으로 초점을 돌려준다.
- 지도 링크 복사에 지도 ID를 포함한다. 초기 연결 중에는 로딩 화면을, 실패하면 다시 연결 버튼을 표시한다. 운영 데이터 로딩 전에 샘플 지도가 먼저 보이던 현상을 없앴다.
- 지도 설정 변경·삭제 전에 행 잠금을 걸어, 같은 버전으로 들어오는 동시 요청 중 오래된 요청을 거절한다.
- 사진 요청은 Content-Length가 없어도 스트림을 읽는 도중 10MB를 넘으면 중단한다. 서버 사진 압축과 읽기 권한 검사는 유지한다.
- 위치 검색·닫기 버튼의 터치 영역과 모바일 입력 글자 크기, 입력 초점 표시를 보완했다.

- 제안 기능 끄기·보관·복원과 이모지 비활성화·재활성화를 추가했다. [설정 기능 검토](STAGE7_SETTINGS_REVIEW.md)에 권한·보존 규칙과 증거를 기록했다.

## 검증 근거

- 단위 검사 29개(초안·사진 복구 9개, 지도 의미 표현 6개 추가): 기존 주제·권한·집계 규칙, 겹친 좌표의 모든 ID 보존, 제한 크기 스트림 경계·취소 검사.
- 4단계 API 검사를 네 기본 주제로 확대했다. 생태·유니버설 디자인 기록과 안전·날씨생활 기록/분석, 사진 실패 후 본문 유지, 잘못된 CSRF·다른 출처의 쓰기 거절, 기존 중복 제출·사진·지도 격리 검사가 통과했다.
- 5단계 API 검사에서 동일 버전의 설정 요청 2개를 동시에 보내 200/412 응답을 확인했다. 검수·댓글·신고·차단·공개 범위·삭제/복구 회귀 검사도 통과했다.
- 6단계 API 검사: 필터·분모·CSV·제안서·근거 변경·비공개 공유 경계 통과. 합성 기록은 검사 종료 후 제거했다.
- 타입 검사와 프로덕션 빌드 통과.
- 인앱 브라우저 360×800, 390×844 지도·목록·상세와 430×932 분석 화면 확인. 360/430px에서 문서 가로 넘침 없음. 지도 출처와 범례 분리 확인. 같은 좌표의 두 기록 선택, 상세 Escape 닫기, 목록 항목으로 초점 복원 확인. 화면 크기 검사는 실제 Android/iOS 검증을 대신하지 않는다.
- 지도 링크 복사 성공 안내와 지도 ID를 포함하는 구현을 확인했다. 브라우저 도구의 클립보드 읽기는 빈 값이어서 실제 휴대전화에서 붙여넣기를 추가 확인해야 한다.
- [겹친 기록 선택 화면](qa/stage7-overlapping-points.png)은 합성 자료다.

## PRD 인수 기준 대조

‘검증’은 명시한 환경의 증거가 있다는 뜻이다. ‘부분’은 요구사항 전체를 통과했다는 뜻이 아니다. 이전 단계 근거는 해당 검토 문서와 검사 스크립트를 참조한다.

| 번호 | 항목 | 판정·증거 또는 남은 일 |

| 1 | 주제 우선 생성·분리 | 부분: 생성 시안·서버 주제 검사 완료. 모든 조합의 사용자 실습 필요 |

## 출시 전 남은 일

1. 23·26번 설정 변경은 [설정 검토](STAGE7_SETTINGS_REVIEW.md), 4번의 핀·범례 평가 기호와 주제별 의미 구분은 [접근성 검토](STAGE7_MAP_ACCESSIBILITY_REVIEW.md)에서 확인했다. 실제 색각·보조기술 사용자 검증은 남아 있다.
2. [파일럿 체크리스트](PILOT_CHECKLIST.md)에 따라 Android Chrome·iOS Safari, 다른 기기 게스트, 위치 거부/허용, 촬영 사진·공유/PDF·스크린리더를 확인한다.
3. 사진 사전 압축·진행률·사진만 재시도를 구현했다. 브라우저에서 8.3MB → 1.24MB로 압축해 저장했다. [사진·초안 검토](STAGE7_RECOVERY_REVIEW.md) 참조. Android/iOS 촬영 원본과 HEIC 디코딩 가능 여부, 실제 통신 단절·복구를 추가 확인한다.
4. 같은 탭·같은 사용자에서 지도/기록별 초안 복구를 구현하고 새로고침 UI를 검증했다. 실제 OAuth 왕복과 게스트 세션 만료는 별도 확인한다. 다른 참여자 식별자로 재입장한 게스트에게 이전 초안을 노출하지 않는다.
5. [성능 검토](STAGE7_PERFORMANCE_REVIEW.md)에서 API 실행 지역을 DB와 같은 서울로 옮겼고, 작은 공개 지도의 설정/분석 p95가 1,458/1,955ms에서 67/77ms로 줄었다. 실제 4G UI 3초, 대표 데이터·동시 참여 API p95 1초 목표는 추가 측정이 필요하다. 홈 로딩 8초 편차 1회도 미확정으로 기록했다. [초대·목록 검토](STAGE7_DIRECTORY_REVIEW.md)에서 초대 실패 안내와 지도 20개 단위 추가 조회·전체 검색을 검증했다. 장기 보관 정리는 운영 검토 대상이다.

다음 작업은 7단계의 남은 기능·실기기 인수 검사다. 통합 판단은 GPT-6 Astra / High, 개별 수정은 GPT-6 Sol / High를 권장한다. 이 검토만으로 8단계 출시를 시작하지 않는다.
