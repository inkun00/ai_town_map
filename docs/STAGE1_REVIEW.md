## 2. 사용자 확정 사항

- 지도 개설자는 Google 로그인.
- Next.js + Supabase(PostgreSQL·Auth·Storage) 사용, 기존 서버 환경 없음.
- 참여자는 초대 코드·닉네임, 학교와 일반 커뮤니티 모두 지원.
- 생성 첫 단계에서 주제를 선택하고 기능·핀 색상의 의미는 주제별로 구성.
- 모든 지도에서 주제에 맞는 다양한 이모지를 개별 포인트에 필수 표시.
- MVP는 기본 분석·수동 제안서, AI는 후속.

## 4. 수행한 검증

- `theme-presets.json`을 실제 JSON 파서로 읽어 5개 주제 key·version 구조를 확인했다.
- 201개 정적 검사를 통과했다: 핀 모드 의존성, 평가 유무와 scheme 일치, 평가 3단계, 질문 타입·선택지, 분류·질문 상한, 이모지 다양성·기본값 참조·label, 생태·날씨·유니버설 디자인 특수 조건, 설계 문서 코드 블록 쌍.
- 수동 교차 검토에서 API의 If-Match 대상인 membership·report의 version 필드를 스키마에 맞췄다.
- 신규 게스트 입장은 기존 인증 사용자의 idempotency와 분리했다. 최초 응답·쿠키 유실은 닉네임 복구로 우회하지 않으며 한계를 문서화했다.
- 서버의 신뢰된 DB 접근을 사용자별 RLS 인가와 혼동하지 않도록 명시했다. 직접 Data API 차단과 서버 업무 인가를 각각 검증할 예정이다.

DB migration, 로그인, API 요청, 실제 Kakao 렌더링, 모바일 레이아웃, 부하 테스트는 수행 전이다. 정적 설정 검증은 이를 대신하지 않는다.

## 5. 남은 준비 항목과 시점

| 항목 | 시점 | 현재 단계 영향 |
|---|---|---|
| Google OAuth·Supabase 프로젝트 실제 설정과 키 | 3단계 | 2단계 샘플 UI에는 불필요 |
| Kakao 키·허용 도메인 | 4단계 | 지도 UI 골격과 실제 SDK 검증을 구분 |
| 사진 worker 실행 환경·HEIC 지원 범위 | 3~4단계 | 처리 인터페이스·상태는 정의 완료 |
| 호스팅 공급자·리전·비용 상한 | 실제 서버 연결 전 검토, 출시 전 확정 | 현재 특정 유료 서비스 개설 안 함 |
| 삭제·세션·초대 보관값과 운영 약관 | 파일럿 전 검토 | 권장값과 확정 사실을 구분 |
| 제품명·브랜드 색상·시각 스타일 | 2단계 | 가칭 ‘모두의 지도’로 진행 가능 |
