# 7단계 — 초대 안내와 지도 목록 개선

작성일: 2026-09-29 · 운영 주소: https://ai-town-map.vercel.app/

## 사용자 동작

- 공개 지도와 내가 참여한 지도를 구분하고 각각 20개씩 불러온다. 다음 페이지가 있으면 ‘더 보기’, 모두 조회했으면 마지막 목록 안내가 나온다. 참여 지도에는 보관 중인 지도도 포함한다.
- 지도 이름·지역 검색과 주제 선택을 서버 조회에 적용한다. 처음 받아 둔 지도에 없어도 검색할 수 있다. 검색어는 최대 100자이며 `%`, `_`도 일반 글자로 취급한다.
- 검색어나 주제가 바뀌면 페이지를 처음부터 조회하고 이전 요청은 취소한다. 취소를 무시하고 도착한 이전 응답도 반영하지 않는다. 다음 페이지 실패 시 기존 목록과 커서를 유지하며 재시도할 수 있다. 연속 클릭은 중복 요청하지 않는다.
- 초대 만료, 철회, 횟수 소진, 보관 지도, 참여 차단, 요청 제한을 구분해 다음 행동을 안내한다. 서버가 응답한 대기 시간도 문구에 반영한다. 코드·닉네임은 실패 후 유지한다.
- 잘못된 코드 형식과 공백 닉네임은 서버에 제출하기 전에 안내한다. 공백·하이픈을 포함한 코드는 정규화해 제출한다. 제출 중 연속 클릭 방지 및 연결 지연 제한을 추가했다.

## 구현과 권한

기존 지도 목록 API의 커서 방식을 화면에 연결했다. 홈 초기 연결에서는 상태·세션을 확인하고, 두 목록은 독립적으로 조회한다. 목록 하나의 실패가 다른 목록이나 로그인·초대 진입을 막지 않는다. 직접 지도 URL과 화면 시안 모드도 유지한다.

페이지 정렬은 `(created_at, id)`의 내림차순이다. 이전에는 JavaScript Date로 커서를 만들면서 PostgreSQL의 마이크로초가 잘려 같은 시각의 기록이 다음 페이지에서 누락될 수 있었다. 이제 UTC 마이크로초 문자열을 보존하고 커서의 날짜·UUID 형식을 검사한다. 이전 밀리초 ISO 커서도 받을 수 있다.

비공개 지도는 공개 검색에 나오지 않는다. 참여 지도 조회에는 세션이 필요하다. 초대의 상세 실패 사유는 입력한 코드가 일치한 경우에만 구분하며, 지도 제목·좌표·참여자 정보는 반환하지 않는다. 없는 코드와 삭제된 지도의 코드는 동일한 일반 오류다. 기존 요청 횟수 제한·CSRF·차단 상태 검사 및 재참여 멱등성은 유지한다.

## 검증 결과

| 검사 | 결과 |
|---|---|
| 단위 검사 | 35개 통과. 추가 6개는 다음 페이지 실패/재시도, 중복 제거, 연속 클릭, 이전 검색 응답 무시, 검색 조건 전달, 초대 문구·입력 검사 |
| 실제 API | 기존 3단계 검사 통과. 5개 지도에 동일한 마이크로초 시각을 지정한 뒤 2개씩 조회해 누락/중복 없음 |
| 서버 검색·권한 | 이름/지역 검색·주제 결합, 일반 `%` 검색, 잘못된 UUID/달력 날짜 커서 422, 익명 참여 목록 401, 비공개 지도 검색 미노출 |
| 초대 경계 | 만료·철회·보관 지도 오류 코드, 소진·차단 거절, 같은 닉네임의 다른 신원, 기존 게스트 재참여 통과 |
| 모바일 크기 UI | 390×844에서 합성 지도 25개를 20→25개로 조회, 생태 필터 13개, 이전 페이지 밖의 01번 지도 검색·열기 |
| 만료 초대 UI | 새 코드 요청 문구, 입력값 유지, 재시도 버튼 확인. 360px에서 문서 가로 넘침 없음 |
| 빌드 | Next.js 프로덕션 빌드와 TypeScript 검사 통과 |

브라우저 검증은 실제 로그인 세션과 개인정보 없는 합성 지도·만료 초대를 사용했다. 검증용 데이터는 검사 스크립트의 finally에서 정리했다. 남아 있는 사용자 지도는 변경하지 않았다.

- [검색 결과 화면](qa/stage7-directory-search.png)
- [만료 초대 안내](qa/stage7-invite-expired.png) — 캡처 속 코드는 정리 완료된 합성 초대로 실제 접근 권한이 없다.

재검증: 설정된 로컬 서버를 실행한 뒤 `RUN_LIVE_PHASE3=1`로 `node scripts/check-live-phase3.mjs`를 실행한다. 모바일 UI 자료가 필요하면 `DIRECTORY_UI_CHECK=1`을 추가한다. `.directory-ui-check.json`이 생성되면 그 파일의 합성 검색어로 검사하고 파일을 삭제하면 정리가 진행된다. 최대 10분 후 자동으로 정리한다. 환경 파일·세션 토큰은 결과 문서나 Git에 포함하지 않는다.

## 남은 일

이 검사는 모바일 크기의 데스크톱 브라우저 검사다. 실제 Android의 키보드·TalkBack·통신 단절과 학교/커뮤니티 사용성 검증은 [파일럿 체크리스트](PILOT_CHECKLIST.md)에 남아 있다. 동시 사용자·대용량 분석과 장기 데이터 보관/백업 복원도 출시 조건이다.

이후 데이터 보관·복구 운영 정책과 대표 데이터량 성능을 [8단계 운영 검토](STAGE8_RETENTION_REVIEW.md)에서 확인했다. 삭제 후 30일 정리 정책을 확정하고 예약했다.
