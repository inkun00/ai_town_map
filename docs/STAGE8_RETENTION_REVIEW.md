# 운영 보관 정책과 대표 데이터량 검증 (2026-09-30)

## 확정 정책

사용자가 지도 또는 위치 기록을 삭제하면 즉시 일반 열람과 집계에서 빠진다. 삭제 시각부터 **30일 이내**에는 기존 권한 규칙에 따라 복구할 수 있다. 30일이 지난 삭제 지도와 그 안의 모든 기록·사진·댓글·신고·검수 이력·제안서·설정·초대는 영구 삭제한다. 개별 기록을 삭제한 경우에도 30일이 지난 기록과 그 사진·댓글·신고·관련 검수 이력을 함께 삭제한다. 개별 삭제 댓글과 제안서도 삭제 후 30일이 지나면 정리한다. 관리자 숨김, 지도 보관, 기능 비활성화는 삭제로 취급하지 않는다.

`app_private.purge_expired_content()`는 일회에 지도 최대 20개, 개별 기록 최대 500개, 댓글 최대 500개, 제안서 최대 200개를 한 트랜잭션에서 처리한다. 남은 자료는 다음 실행에서 처리한다. `pg_cron`의 `aimap-retention-30d` 작업은 매일 17:00 UTC, 즉 한국 시간 02:00에 호출한다. 따라서 30일을 넘긴 직후가 아니라 **30일 경과 후 다음 성공 실행 때** 실제 삭제된다. 함수는 DB 소유자만 실행할 수 있고 앱 서버 역할에는 실행 권한이 없다. 복구 기간 내 자료가 삭제되지 않는 경계와 종속 행 정리는 합성 DB에서 검증했다.

DB 백업은 Supabase 대시보드에서 일일 생성 상태를 확인했다. 실제 복구 연습은 운영 DB에 복원하면 서비스에 영향이 있으므로 아직 하지 않았다. 백업 보관 기한과 복원 가능 시점은 요금제/설정에 의존하며, 삭제 후 30일 정책은 **운영 DB의 활성 자료**에 적용된다. 백업에서 지워지는 시점이나 즉시 완전 소거를 보장하는 정책은 아니다. 이 서비스의 사진은 현재 `app.observation_photos.content`의 DB 바이트로 저장되어 DB 백업에 포함된다. 별도 안전한 프로젝트/환경에서 수행할 [복원 연습 절차](BACKUP_RESTORE_RUNBOOK.md)를 정리했다.

운영 점검은 `npm run db:audit-retention`으로 삭제 기간별 건수와 사진·개인정보 관련 잔여 건수를 **식별자 없이** 출력한다. 예약 검증은 `cron.job`의 작업 이름, 명령, 활성 여부를 확인하고 실제 실행 뒤 `cron.job_run_details`의 상태를 확인한다. 실패가 이어지면 원인을 수정한 뒤 소유자 권한으로 함수를 수동 실행하고 다시 집계한다. `npm run db:schedule-retention`은 예약을 재설정하지만 즉시 정리를 수행하지 않는다.

## 대표 데이터량

운영 앱의 비공개 **합성 지도**에 기록 100→500→1,000건과 WebP 사진 5→9→14장을 넣고, 서울 리전의 분석 API를 단계마다 순차 30회 호출했다. 자세한 원시 요약은 [측정 JSON](qa/volume-performance.json)에 있다. 합성 지도·계정·사진은 측정 후 제거했고 운영 집계 전후가 같음을 확인했다.

| 기록 수 | 분석 API p50 | 분석 API p95 | 최대 응답 크기 | 요청 실패 |
| ---: | ---: | ---: | ---: | ---: |
| 100 | 66 ms | 91 ms | 80 KB | 0/30 |
| 500 | 88 ms | 116 ms | 377 KB | 0/30 |
| 1,000 | 110 ms | 167 ms | 747 KB | 0/30 |

이 결과는 개발자 Windows 호스트에서의 전체 응답 요청 시간이다. 모바일 렌더링, 4G 대역폭·지연, 동시 사용자, 1,000건 초과, 사진이 많은 지도는 측정하지 않았다. 특히 분석 응답은 1,000건에서 약 747 KB이므로 실제 휴대전화의 데이터 사용량과 화면 반응을 별도로 확인해야 한다. 현재 수치만으로 파일럿 전체 성능 기준을 통과했다고 판정하지 않는다.

## 확인 결과와 남은 조건

- 마이그레이션 구문·권한, 30일 경계, 반복 실행의 멱등성, 삭제 지도와 사진·댓글·신고·감사·제안서 종속 자료 삭제를 합성 PostgreSQL 환경에서 확인했다.
- 운영 DB에 새 마이그레이션을 적용하고 `aimap-retention-30d`의 일정·활성 상태를 확인했다. 예약 후 첫 **실제 실행 결과**는 아직 확인 전이다.
- 운영 점검 시 영구 정리 기한이 지난 지도·기록·댓글·제안서가 없었다. 성능 검증 자료는 모두 제거했다.
- 백업 복원 연습, Android 실기기의 위치·카메라·키보드·TalkBack·4G 시험, 동시 참여 부하는 다음 검증 조건이다.

다음 단계의 Android 실기기/에뮬레이터 UX·접근성 검증에는 **GPT-6 Sol / High**, 권한·개인정보·운영 출시 판정에는 **GPT-6 Astra / High**를 권장한다. 모델 추천은 실제 실행 모델 변경을 의미하지 않는다.
