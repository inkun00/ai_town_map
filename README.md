# 모두의 지도

동네의 장소와 환경을 주제별 이모지 포인트로 기록하는 모바일 커뮤니티 지도 웹앱입니다. Google 회원가입에서는 교사와 학생을 선택합니다. 교사는 지도를 만들고 탐험게임을 운영하며, 학생은 이메일 형식의 아이디와 비밀번호로도 바로 가입·로그인할 수 있습니다. 실제 이메일이나 확인 메일은 필요하지 않습니다. 기존 이메일 인증 계정은 별도 이메일 로그인으로 계속 사용할 수 있습니다. 계정 없는 참여자는 초대 코드와 닉네임으로 입장합니다. [PRD](docs/PRD.md)와 [개발 계획](docs/DEVELOPMENT_PLAN.md)에 기능 범위와 단계별 모델 권장을 기록했습니다.

## 로컬 실행

Node.js 22 이상에서 `npm install` 후 [`.env.example`](.env.example)을 참고해 `.env.local`을 만듭니다. Supabase와 Google OAuth 설정은 [3단계 설정 안내](docs/STAGE3_SETUP.md)를 따릅니다. 카카오맵 JavaScript 키에 로컬 주소를 등록해야 실제 지도가 표시됩니다.

```bash
npm run db:migrate
npm run dev -- -p 3001
```

`http://localhost:3001`에서 지도를 엽니다. 서버 설정이 없으면 샘플 UX가 표시됩니다. 서버 설정이 있으면 지도·회원·기록·사진이 DB에 저장됩니다. 카카오 키가 없으면 실제 지도 대신 설정 안내가 표시됩니다.

검증 명령은 `npm run db:check-schema`, `npm test`, `npm run typecheck`, `npm run build`입니다. 실제 DB API 연동은 합성 자료를 생성·삭제하는 `RUN_LIVE_PHASE4=1 node scripts/check-live-phase4.mjs`로 검사할 수 있습니다.

지도와 초대 코드에 참여 인원·누적 사용 횟수 상한을 적용하지 않습니다. 기존 코드를 포함한 변경에는 `011_unlimited_map_invites.sql`이 필요하며 앱 배포 전에 `npm run db:migrate`로 적용합니다. 코드 만료·폐기, 차단과 인증 실패 검사는 유지합니다. 실제 동시 처리 규모는 서버·DB 자원에 따라 달라집니다.

여러 참여자가 작성 중 새 이모지를 추가해도 다른 참여자의 기록은 계속 저장됩니다. 질문·분류·평가 등 실제 설정이 바뀌면 입력과 사진을 유지한 채 **지도 설정 다시 확인**으로 갱신하고, 변경된 항목을 확인한 뒤 저장합니다. 합성 학생 30명의 동시 등록과 중복 요청 방지는 `RUN_LIVE_CLASSROOM_RECORDS=1 node scripts/check-live-classroom-records.mjs`로 검사하며, 운영 앱 검증에는 `LIVE_APP_ORIGIN=https://ai-town-map.vercel.app`을 함께 설정합니다. 이 검사는 실제 학생 기록을 변경하지 않고 생성한 검사 자료만 정리합니다.

## 배포

Vercel 환경 변수, Supabase DB 풀러, OAuth 리다이렉트, 카카오 SDK 도메인은 [배포 안내](docs/DEPLOYMENT.md)를 따릅니다.

## 관광 지도

**지도 만들기 → 관광**에서 문화재·유적지, 박물관·전시, 공연·문화공간, 놀이·체험시설, 축제·행사, 자연·경관명소, 먹거리·시장, 교통·여행안내, 휴식·편의시설을 기록합니다. 9개 분류에 관광 이모지 162개를 제공하며, 핀 색상은 분류를 나타냅니다. 사진·설명·링크·댓글·통계·개선 제안은 기존 지도와 같은 방식으로 사용합니다. 볼거리·체험 특징, 운영 시간·행사 기간, 요금, 편의시설 질문은 모두 선택 입력입니다.

기존 DB에는 `node scripts/register-tourism-theme.mjs`로 관광 템플릿만 등록할 수 있습니다. 서버 환경의 `DATABASE_ADMIN_URL`을 사용하며 기존 템플릿·지도·기록은 변경하지 않습니다. 처음 설치하는 환경에서는 기존 `npm run db:migrate`가 함께 등록합니다. 합성 교사와 지도만 생성·삭제하는 실제 API 검사는 `RUN_LIVE_TOURISM=1 node scripts/check-live-tourism.mjs`로 실행하며, 운영 검사에는 `LIVE_APP_ORIGIN=https://ai-town-map.vercel.app`을 지정합니다.

## 관광·문화유산 길찾기

관광·문화유산 지도 하단의 **길찾기**를 누르고 등록 포인트를 방문할 순서대로 고릅니다. 최대 12곳까지 선택하고 순서를 바꾸거나 제외할 수 있습니다. 모든 구간은 자동차 기준으로 계산하며 이동수단 선택 없이 하나의 길찾기로 제공합니다. 선택한 계획은 기기와 사용자·지도별로 저장되며, 공용 기록은 변경하지 않습니다. 기존에 저장한 도보 구간은 방문 순서를 유지하고 자동차 기준으로 다시 계산합니다.

길찾기는 카카오모빌리티 자동차 API의 실제 도로 경로·거리·예상시간을 이용합니다. `.env.local`과 Vercel 서버 환경에 `KAKAO_REST_API_KEY`를 설정합니다. 지도 표시용 JavaScript 키와 다르며 `NEXT_PUBLIC_` 변수에 넣지 않습니다. [공식 설정 안내](https://developers.kakaomobility.com/guide/navi-api/start.html)를 참고하세요. 경로를 찾지 못한 구간은 선·거리·시간을 임의로 추정하지 않습니다.

시간은 조회 시점 기준 예상값이며 관람·휴식 시간은 포함하지 않습니다. 최근 성공 구간은 서버 메모리에 최대 2분 재사용하고, 화면에서도 계산 시각과 오래된 결과 안내를 표시합니다. 일부 구간이 확인되지 않으면 확인된 구간만 합산합니다. **전체 경로 보기 → 백지도 → 지도 이미지 복사 / 지도 PNG 저장**으로 방문 순서·도로 동선·구간별 거리와 시간·출처를 포함한 지도를 공유합니다.

서버는 이 지도에서 공개된 포인트 ID의 좌표만 사용합니다. 키·사용자 계정·제목·본문·현재 GPS는 길찾기 제공자에게 보내지 않습니다. 외부 호출 전 DB 연결을 해제하고 완료 후 지도·기록 상태와 좌표를 다시 확인합니다. 요청 수·응답 크기·좌표 수·시간을 제한하며 DB 마이그레이션은 필요 없습니다.

## QR 보물 찾기

교사는 탐험게임 제작 화면에서 장소를 선택하고 **QR 보물 찾기** 미션을 추가합니다. 점수와 안내를 저장한 뒤 **보물찾기 QR 카드 → QR 인쇄**로 카드를 출력해 해당 장소에 배치합니다. 관찰·체크리스트·퀴즈에도 장소 확인 방식을 **QR 스캔**으로 지정할 수 있습니다. 게임방에서는 방을 생성할 때 고정한 미션 기준으로 QR을 인쇄합니다.

학생은 게임방 코드로 입장하고, 교사가 게임을 시작하면 **QR 카드 스캔하기**를 누릅니다. 카메라, QR 사진 또는 QR 주소·코드 입력으로 장소를 확인할 수 있습니다. 보물 찾기는 **보물 획득**을 눌러 점수를 받으며, 관찰·체크리스트 응답은 교사의 승인 후 점수를 받습니다. GPS가 부정확하거나 위치 공유가 꺼져 있어도 QR 미션은 수행할 수 있습니다. 기존 GPS 방식 미션은 위치 확인 규칙을 유지합니다.

스마트폰의 기본 QR 카메라로 열어도 같은 브라우저에서 참여한 게임방으로 이어집니다. 이전 게임방에 입장하지 않았거나 세션이 만료되면 게임방 코드로 먼저 참여합니다. 인쇄 QR은 해당 게임의 장소 확인에 사용하고, 학생별 제출 증명은 방·학생·장소·종료시간을 서버에서 확인합니다. 스캔만으로 점수를 주지 않으며 중복 제출로 점수가 반복 지급되지 않습니다. 새로운 환경 변수나 DB 마이그레이션은 필요 없습니다.

## AI 참고 제안과 학생의 최종 글

지도의 **통계·분석 → AI 참고·나의 글**에서 발견 제안, 비슷한 기록 묶기, 여러 사람의 관점, 다음 탐험 질문, 개선 아이디어를 살펴봅니다. 모든 주제에서 사용할 수 있으며 학년 제한은 없습니다. AI 카드는 참고 제안입니다. 학생은 근거 기록을 확인하고 자신의 분석·개선 제안·판단 이유·후속 조사 계획을 직접 작성합니다. AI 결과를 학생 글에 자동으로 채우거나 제출하지 않습니다.

학생 글은 지도와 참여자별로 비공개 저장합니다. 초안 저장과 최종 글 저장을 구분하며, 기존 공용 제안서 게시 기능과 독립적입니다. 닉네임 참여도 가능하지만 다른 기기에서 같은 글을 이어 쓰려면 같은 계정으로 로그인해야 합니다. DB 마이그레이션 `010_student_analysis.sql`이 필요합니다.

승인받은 학생용 Gemini API 환경의 서버 설정을 `.env.local`과 Vercel에 각각 입력합니다. 비밀 키는 커밋하거나 `NEXT_PUBLIC_` 변수에 넣지 않습니다.

```dotenv
GEMINI_STUDENT_USE_APPROVED=true
GEMINI_API_KEY=승인받은_API_키
GEMINI_MODEL=gemini-3.1-flash-lite
```

설정되지 않으면 AI 생성만 준비 안내를 표시하며, 기본 통계와 학생 글 작성·저장은 작동합니다. Gemini 호출은 서버가 현재 필터의 게시 기록을 조회해 실행합니다. 사용자가 작성한 최신 최대 50건의 제목·설명·평가·질문 응답·개선 아이디어를 텍스트로 분석하며, 현재 필터의 전체 게시 기록에서 계산한 서버 집계도 참고합니다. 등록일을 관찰일이나 시설 수로 해석하지 않습니다. 주제·질문은 기록 당시 설정 버전을 따릅니다. 작성자 계정·닉네임·정밀 좌표·외부 링크 내용·게임 위치는 전달하지 않습니다. 본문에 직접 적힌 개인정보는 생성 전에 확인해야 합니다.

사진 분석 기능은 제공하지 않으며, 등록 사진과 지도 이미지는 AI에 전송하지 않습니다. 위치포인트의 사진 등록과 원본 사진 보기 기능은 계속 사용할 수 있습니다. 외부 링크도 방문하지 않습니다. AI 결과의 근거 ID를 서버에서 검증하고, 생성 중 원본 기록이 달라지면 다시 생성하도록 안내합니다. 학생 글의 저장 충돌도 입력 내용을 유지한 채 안내합니다. 실제 Gemini 텍스트 생성 검증은 `RUN_LIVE_AI_ANALYSIS=1 RUN_LIVE_GEMINI=1 node scripts/check-live-ai-analysis.mjs`로 명시적으로 실행하며, 합성 기록을 생성·삭제하고 모델을 한 번 호출합니다.
